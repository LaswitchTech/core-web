# PHP Built-in Web Server Router Configuration

## Overview

The `Builtin` class provides a static helper that generates a `router.php` file for use with PHP's built-in development web server (`php -S`). It emits a small router script that returns `false` for static files (letting PHP serve them directly via its native static file handler) and forwards all other requests to the application's entry point (`index.php`). This is intended strictly for local development environments — not production use.

## Responsibilities

- **Generate a `router.php` file** containing:
  - A router callback that intercepts every request before PHP serves it.
  - File existence checks using `is_file()` and `is_dir()` to bypass dynamic routing for static assets (CSS, JS, images).
  - A fallback rewrite rule that passes all non-static requests to the application's entry point via a custom `$_SERVER` initialization (`SCRIPT_FILENAME` pointing to `index.php`).

### Generated Behavior Table

| Request Type | Action Taken by router.php |
|--------------|-----------------------------| 
| Static file (exists on disk) | Returns `false` so PHP serves it directly as-is |
| Non-static file / dynamic route | Rewrites URL to `index.php` and sets appropriate `$_SERVER` variables for routing |

## Architecture

### Internal Generation Flow

Builtin::generate(): string is a pure static factory that writes a PHP script:

| Step | Action | Detail |
|------|--------|--------|
| 1 | Write opening `<?php` tag with standard comment header | Identifies file as auto-generated by Core-Web framework's built-in router module (includes the URL path for logging) | 
| 2 | Generate the static file bypass logic | Uses `is_file()` and `is_dir()` to check if `$uri` points to a physical asset on disk; returns `false` if so. This allows PHP's built-in server to serve CSS, images, JS files directly without hitting application routing. |
| 3 | Write the catch-all rewrite block | When a request does not match an existing file OR directory, sets `$_SERVER['SCRIPT_FILENAME']` to point to the user-facing entry (`index.php`) and routes through the normal framework dispatcher. |

### Method Signature Summary

| Method | Arguments | Return Type | Description |
|--------|-----------|-------------|-------------|
| `generate(): string` | none | `string` | Returns router.php content as an unformatted PHP script string ready for file writing. No `$subdir` parameter: subdirectory routing is not used with built-in server since it always runs from the project root (e.g., `php index.php start /path/to/app`). The URL and path info variables are set dynamically in the generated PHP code so they contain accurate values at runtime regardless of where files live physically on disk. |

### Usage Example — Development Workflow

```bash
# In the app's root directory:
php -S localhost:8000 router.php   # ← generated by Builtin::generate()
```

The built-in PHP web server serves the `router.php` file as its request dispatcher. On each incoming request to `http://localhost:8000/some/path`, the embedded callback executes: checks if `/some/path` is a real file → serves it; otherwise rewrites to `index.php`.

### Generated Output Example (Full router.php): 

```php
<?php
// Auto-generated by Core-Web Builtin Router Configuration Generator
// Used for development only — not for production deployments.

$uri = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH) ?? '';

if ($uri !== '' && is_file(__DIR__ . $uri)) {
    return false;  // Serve the file directly
}

// Rewrite all other requests to index.php
$_SERVER['SCRIPT_FILENAME'] = __DIR__ . '/index.php'; 
$_SERVER['SCRIPT_NAME'] = '/index.php';

require __DIR__ . '/index.php';
```

## Limitations

- **Development use only** — the built-in PHP server is never intended for production; this module exists solely to simplify local development workflows. No performance tuning, TLS, or multi-worker support is provided.
- **Single-worker limitation** — `php -S` runs one synchronous worker per process. There is no mechanism to spawn multiple workers for parallel request processing.

## Future Enhancements

- Add a built-in task runner that detects the framework installation and automatically generates + launches the router script with colored output (like Laravel's `php artisan serve`).
