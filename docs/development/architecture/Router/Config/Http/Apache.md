# Apache Web Server Configuration Generator

## Overview

The `Apache` class provides a static helper that generates an `.htaccess` file compatible with both single-directory and subdirectory deployments on Apache HTTPD servers. It produces mod_rewrite rules that route all non-static-file requests to the application's entry point (`index.php`). The generated `.htaccess` respects common shared-hosting and virtualhost configuration constraints by relying only on standard, enabled modules (mod_rewrite and PHP's built-in handler).

## Responsibilities

- **Generate an `.htaccess` snippet** containing a `RewriteEngine On` directive followed by conditional rules for:
  - Serving existing physical files directly (`RewriteCond %{REQUEST_FILENAME} !-f`).
  - Serving existing directories as-is (`RewriteCond %{REQUEST_FILENAME} !-d`).
  - Forwarding all remaining requests to `index.php` via a `RewriteRule`.
- **Handle subdirectory deployments** by optionally inserting the application's subdirectory path into the rewrite target, ensuring that URLs like `/subdir/users/profile` resolve correctly inside a virtualhost or shared host.
- **Provide safe defaults** — when the `$subdir` argument is empty string `''`, generates rules for root deployment (no subdirectory prefix in targets).

### Generated Rule Set

| Condition / Rule | Purpose                                    |
|-------------------|--------------------------------------------|
| `RewriteEngine On`  | Enables mod_rewrite engine                |
| `!-f` condition     | Skip rewrite when a physical file exists   |
| `!-d` condition     | Skip rewrite when a physical directory exists | 
| `RewriteRule`       | Catch-all rule forwarding to index.php     |

## Architecture

### Internal Generation Flow

Apache::generate() is a pure static factory with no external dependencies:

| Step | Action | Detail |
|------|--------|--------|
| 1   | Build header comments | Adds standard `.htaccess` comment identifying file as auto-generated by Core-Web Router subsystem. |
| 2   | Output `RewriteEngine On` | Required directive; always present regardless of deployment mode. |
| 3   | Evaluate `-f` condition | When `$subdir` is non-empty, prepends `^{$subdir}` to the pattern; when empty (root), uses `^(.*)$`. The `-f` cond skips the rule if a physical file exists on disk. |
| 4   | Evaluate `-d` condition | Same `$subdir` prefix logic; skips the rule when the target is an existing directory. |
| 5   | Write final `RewriteRule` | Routes all unmatched requests to `/index.php` (root deploy) or `$subdir/index.php` (subdirectory deploy), always with `[QSA,L]` flags for QueryString Append and Last-rule-processing. |

### Method Signature Summary

| Method | Arguments | Return Type | Description |
|--------|-----------|-------------|-------------|
| `generate(?string $subdir): string` | `$subdir` — optional application path (e.g., 'myapp') | `string` | Returns full `.htaccess` content as a multi-line string ready for file writing. |

### Generated Output Examples

Root deployment (`$subdir = ''`):

```apache
RewriteEngine On
# Serve existing files and directories directly
RewriteCond %{REQUEST_FILENAME} !-f  
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^(.*)$ index.php [QSA, L]
```

Subdirectory deployment (`$subdir = 'myapp'`):

```apache
RewriteEngine On
# Serve existing files and directories directly
RewriteCond %{REQUEST_FILENAME} !-f  
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^myapp/(.*)$ myapp/index.php [QSA, L]
```

This means the same class can generate both configurations depending on $subdir being empty or not.

### Usage Example — Framework Bootstrap Integration

During the `router.register` hook, Bootstrap typically writes the generated config to disk:

```php
use Laswitchtech\CoreWeb\Router\Config\Http\Apache;

// In a router register handler or post-bootstrap plugin setup:
$htaccessContent = Apache::generate('/myapp');
file_put_contents('./.htaccess', $htaccessContent);
```

In practice deployments, `generate()` is called during application initialization and the result written to the `.htaccess` file in the web root. The framework provides a CLI command (`core.install`) or admin panel option that triggers this auto-generation of server config during the first-time setup wizard.

## Limitations

- **mod_rewrite dependency** — the generated `.htaccess` requires mod_rewrite to be enabled on the Apache instance (not all shared hosts enable it by default; extensions need to check).
- **Single-file output only** — generates only the `.htaccess` content as a string; calling code must write it to disk. There is no built-in file-writing or rollback logic in this generator.

## Future Enhancements

- Add a `generateAll()`: static method that produces all server config files (Apache + Nginx + IIS + Built-in) for one deployment target, used by the CLI installer command.
- Add validation — verify mod_rewrite is available before generating and writing file contents to disk.
- Support for `.htpasswd` generation alongside auth-required routes.
- Optional support for `FallbackResource` directive (Apache 2.4+) as an alternative to `RewriteRule` when that directive is preferred over mod_rewrite.
