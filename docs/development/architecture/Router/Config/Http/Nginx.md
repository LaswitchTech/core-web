# Nginx Web Server Configuration Generator

## Overview

The `Nginx` class provides a static helper that generates an Nginx server block snippet for Core-Web deployments. It produces a `try_files` location block that routes all requests to the application's entry point, with optional fastcgi configuration for PHP processing. The generated snippet is intended to be included inside the `server {}` context of an Nginx configuration file.

## Responsibilities

- **Generate an `nginx.conf` snippet** containing a location block with:
  - A `location /` block that routes all requests via `try_files`.
  - An optional PHP-FPM `location ~ \.php$` block for request body handling (fastcgi_pass, SCRIPT_FILENAME variables).
- **Handle subdirectory deployments** by prepending the application's subdirectory to both location paths and fastcgi configuration targets.
- **Serve existing files/directories directly** via Nginx native static file serving before routing the unmatched requests to PHP.

### Generated Configuration Blocks

| Block | Directive | Purpose |
|-------|-----------|---------|
| `location /` | `try_files` | Routes matched requests to index.php while allowing direct access to files/dirs |
| `location ~ \.php$` | `fastcgi_pass`, `SCRIPT_FILENAME`, etc. | PHP processing configuration (optional, included only when generating for deployments) |

## Architecture

### Internal Generation Flow

Nginx::generate() is a pure static factory with no external dependencies:

| Step | Action | Detail |
|------|--------|--------|
| 1 | Build header comments | Adds standard comment identifying file as auto-generated by Core-Web Router subsystem. |
| 2 | Output `server` block opening | `listen`, `root` (web root path), `index index.php` — all inside one server {} block | 
| 3 | Write `location / { }` block with try_files rule | When `$subdir` is non-empty, prepends to the URI pattern; when empty, uses `/` directly. The generated `try_files $uri $uri/ /index.php$is_args$args;` is replaced with a version that correctly handles subdirectory deployments. |

### Method Signature Summary

| Method | Arguments | Return Type | Description |
|--------|-----------|-------------|-------------|
| `generate(?string $subdir = null): string` | `$subdir` — optional application path (e.g., 'myapp') or empty/null for root deploy | `string` | Returns full nginx.conf snippet as a multi-line string ready for inclusion in server block. |

### Generated Output Examples

Root deployment (`$subdir = null` or `''`):

```nginx
location / {
    try_files $uri $uri/ /index.php$is_args$args;
}
```

Subdirectory deployment (`$subdir = 'myapp'`):

```nginx
location /myapp {
    try_files $uri $uri/ /myapp/index.php$is_args$args;
}
```

### Usage Example — Framework Bootstrap Integration

During the `router.register` hook, Bootstrap writes the generated config:

```php
use Laswitchtech\CoreWeb\Router\Config\Http\Nginx;

// In a router register handler or post-bootstrap plugin setup:
$nginxSnippet = Nginx::generate('/myapp');
file_put_contents('./nginx.conf', $nginxSnippet);
```

In practice, deployments use the CLI installer command (`core.install`) that triggers auto-generation of all server configs (Apache + Nginx + IIS + Built-in) during first-time setup.

## Limitations

- **Single-file output only** — generates only the nginx.conf content as a string; calling code must write it to disk. There is no built-in file-writing or rollback logic in this generator.

## Future Enhancements

- Support for HTTP/2 and TLS configuration blocks (`listen 443 ssl`).
- Add SSL certificate directives (`ssl_certificate`, `ssl_certificate_key`) with auto-generation of self-signed certificates for development environments.
- Optional Gzip/Brotli compression directives and caching headers baked into the snippet generator.
- Add a validation helper to check that the Nginx config syntax is valid on the target system before writing.
